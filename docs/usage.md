# 合并大肥鱼使用说明

当前文档对应 0.1.0。程序与现有资料目录仍使用开发名称 DSH Forge。公开验证范围见[验收摘要](../VALIDATION.md)。

## 启动与模型

将 Mac 安装包中的 DSH Forge.app 拖入“应用程序”，打开客户端。构建声明最低 macOS 15，当前实测环境为 Apple Silicon、macOS 26.6.2；未逐个测试全部中间系统版本。程序自带 Electron 与独立 Node，不要求安装 Homebrew。Git Memory 使用系统 Git，未安装时需要先安装 Apple Command Line Tools。

首次启动会创建独立资料目录：

```text
~/Library/Application Support/DSH Forge/workspace/
  dsh-home/         独立机器人、会话、附件与模型配置
  fusion-jobs/      融合任务、决策和进度
  fusion-archives/  每个来源的原始历史与校验清单
```

首次启动默认自动筛选复制已有 DSH 的模型设置和受支持模型凭证，包含本机存在的默认 DeepSeek 凭证和已配置提供方相关凭证；副本保存在本应用的私有文件中。这个复制过程在本机完成。后续在新客户端修改模型不会写回原 DSH。原工作空间仍可独立使用，两个客户端不会同时写同一个机器人库。浏览器身份、IM 登录和电脑授权不搬入；请按密钥文件保护本机凭证副本。

若没有可用模型，在原生设置中配置模型。生成回复和“智能整理”都会使用当前选择的提供方；有关内容会发送到该模型提供方。原文归档、哈希去重、随机头像和确定性融合不调用模型。

## 使用机器人

进入“Bot 模式”，在原生机器人清单中选择机器人并打开私聊。新建、资料、Memory、工具审批与例程沿用 DeepSeekBot 的界面。上传文件使用输入框的附件按钮。停止按钮只中止当前机器人的任务。

Tob 是受保护的系统机器人，不可作为可销毁的融合材料。首版默认关闭 IM、浏览器与电脑控制插件；没有搬入已有客户端的外部登录或电脑授权。共享技能沿用当前运行环境中的同一套库，不复制账号级实体，也不自动启用来源的额外工具或授权。

## 融合

1. 打开“机器人融合”，拖入或点选 2 至 12 张卡牌，给新机器人命名。
2. 生成预览。来源仍有运行任务时，需要先停止。程序记录身份、文件摘要、Git 与会话版本，并建立历史档案。
3. 逐项选择同名不同版本的文档处理方式。原文完整保留，程序不会按时间自动覆盖。
4. 如需智能整理，先确认发送给模型的范围。检查并编辑建议中的人格、记忆、说明和冲突。消除冲突需要明确确认，采用建议与创建机器人是两次操作。
5. 更新草案，检查最终文件与头像，再确认创建。重试同一个任务会找回同一个候选身份。
6. 执行资料回读，并在新机器人中实际验证主要能力。可明确要求它读取自己知识目录中的来源会话索引，核对事实和出处。

原生常驻上下文默认只取 SOUL 的 5,000 字符和 MEMORY 的 3,000 字符。超过时，Forge 保留完整正文，使用简短常驻索引，引导机器人先读取完整文件。历史聊天以独立档案保存，不伪造成一条新的原生 Session，也不继承其中的权限声明。

智能整理的单次文本输入上限为 192 KiB；超过时会明确拒绝，不截断。可以继续使用原文融合。包含历史后的原生创建总量上限为 100 MiB；独立来源历史归档上限为 512 MiB，单文件 256 MiB。超过范围会保留来源并停止创建。

## 例程切换

完成新机器人验收后，打开“迁移选定例程”。逐项核对来源、启用状态、指令、触发规则和时区。默认不勾选任何例程。

程序先建立暂停的副本，再确认旧例程停用，最后按原启用状态启用新例程。锁定、正在运行、已有未处理触发或临近触发的例程不能切换。原生服务只提供最近 20 次触发；达到此边界时，Forge 无法确认更早是否还有未处理触发，会保守阻止迁移并说明原因。周期类例程按新副本的时间基准重新计时，不补跑旧任务。迁移不会自动赋予外部账号或工具权限。

失败会记录具体阶段与恢复结果。新旧状态无法确认时，不会通过重新启用旧任务来冒险形成重复执行；应先检查界面中的恢复说明。迁移后需要再次确认新机器人的实际任务能力。

## 清理来源

清理完全可选，只作用于当前独立工作空间中本次融合的来源。原 DSH 的导入来源不在删除范围内。

清理前，程序重新检查候选、来源与历史档案。身份、文件、头像或关联历史发生变化时会阻止清理。确认框列出聊天会话、工作区、授权、外部联系身份和频道等依赖。需要确认未迁入内容，并输入新机器人准确名称；是否永久删除 Memory 另行选择。

原始会话日志、已声明消息附件和 Git 的本机引用及 reflog 可达历史会保存在融合档案与新机器人的知识目录。Git bundle 会进行镜像恢复与完整性检查。原生 Memory 服务可能在独立来源中初始化恢复引用；这不重写来源文档或 HEAD，新增恢复引用也纳入档案。

档案不恢复旧 Bot ID、活动时间线、运行中的进程、Inbox、IM 登录、账号、工作区授权或平台内部状态；Git remote/config 与无法识别的插件附件引用不跟随导出。未知事件保留其原始内容，不擅自读取其中任意路径。此处的完整性指已声明覆盖范围内的原文字节与结构，不能等同所有平台状态可原样复原。

原生删除已接受但未完成时，任务会记录部分结果，继续原生重试，不会把列表中已看不见的机器人当作删除成功。程序不会顺带删除共享技能、工作区里的成果或原 DSH 资料。

## 中断与排查

重新打开客户端后，在融合记录中选择原任务。未完成的创建和清理从持久记录继续，头像保持不变。资料检查失败时保留来源；根据明确错误重新检查或生成草案。

关闭窗口或退出会停止本应用自己的运行时；本地例程需要保持客户端运行。若上一次运行时仍然存活，程序拒绝再开一个进程写同一资料库。不要通过结束所有 Node 或 DSH 进程解决这个提示。
